## Root Configuration Files

### `package.json`
**Purpose**: Project configuration and dependency management
**Usage**: 
- Defines npm scripts for development, building, testing, and database operations
- Lists all project dependencies (React, Next.js, Prisma, UI libraries, etc.)
- Contains Prisma seed configuration
- **Key Scripts**:
  - `dev`: Start development server
  - `build`: Build for production
  - `db:migrate`: Run database migrations
  - `db:seed`: Seed database with sample data
  - `db:studio`: Open Prisma Studio
- **Dependencies**: Next.js 15, React 18, Prisma, NextAuth, TailwindCSS, shadcn/ui components, Zod, Framer Motion, and more

### `next.config.js`
**Purpose**: Next.js framework configuration
**Usage**:
- Configures server external packages (`@prisma/client`, `bcryptjs`)
- Sets up image optimization with remote patterns
- Configures TypeScript build settings
- Defines output file tracing root
- **Key Settings**:
  - Image domains: localhost, unsplash.com, placeholder.com
  - TypeScript errors ignored during build (for development flexibility)

### `tsconfig.json`
**Purpose**: TypeScript compiler configuration
**Usage**:
- Configures TypeScript compilation settings
- Sets up path aliases (`@/*` maps to project root)
- Defines included/excluded files
- Enables strict type checking
- **Key Settings**:
  - Target: ES5
  - Module: ESNext
  - JSX: preserve (for Next.js)
  - Base URL: `.` (project root)

### `tailwind.config.ts`
**Purpose**: TailwindCSS configuration
**Usage**:
- Defines custom theme colors, fonts, spacing, and animations
- Configures content paths for Tailwind CSS scanning
- Sets up custom design tokens (colors, shadows, gradients)
- Defines custom keyframes and animations
- **Key Features**:
  - Custom color palette (primary, secondary, accent colors)
  - Custom animations (fade-in, slide-in, scale-in, bounce-in, etc.)
  - Custom shadows and gradients
  - Dark mode support
  - Custom font families (Inter, JetBrains Mono)

### `postcss.config.js`
**Purpose**: PostCSS configuration for CSS processing
**Usage**:
- Configures PostCSS plugins
- Enables TailwindCSS and Autoprefixer
- Processes CSS files before bundling

### `middleware.ts`
**Purpose**: Next.js middleware for route protection
**Usage**:
- Protects authenticated routes using NextAuth middleware
- Redirects unauthenticated users to signin page
- Allows public access to auth pages (signin, signup, verify, etc.)
- **Protected Routes**:
  - `/dashboard`
  - `/doctors`
  - `/engineers`
  - `/teachers`
  - `/lawyers`
- **Public Routes**:
  - `/signin`
  - `/signup`
  - `/verify`
  - `/forgot-password`
  - `/reset-password`

### `vitest.config.ts`
**Purpose**: Vitest testing framework configuration
**Usage**:
- Configures test environment (Node.js)
- Sets up TypeScript path resolution for tests
- Defines test file patterns (`tests/**/*.test.ts`)

### `next-env.d.ts`
**Purpose**: Next.js TypeScript environment definitions
**Usage**:
- Auto-generated by Next.js
- Provides TypeScript types for Next.js APIs
- Should not be manually edited

## Application Routes (app/)

### Root Layout and Pages

#### `app/layout.tsx`
**Purpose**: Root layout component for entire application
**Usage**:
- Provides HTML structure (`<html>`, `<body>`)
- Wraps application with SessionProviderWrapper
- Configures metadata (SEO, Open Graph, Twitter cards)
- Loads Inter font from Google Fonts
- Imports global CSS styles
- **Key Features**:
  - SEO metadata configuration
  - Font loading optimization
  - Session provider wrapper

#### `app/page.tsx`
**Purpose**: Home page (root route)
**Usage**:
- Redirects to `/signin` page
- Acts as entry point for unauthenticated users
- Simple redirect component (no UI rendered)

#### `app/robots.ts`
**Purpose**: Robots.txt configuration for search engines
**Usage**:
- Defines which pages/search engines can crawl
- Configures sitemap location
- Helps with SEO

#### `app/sitemap.ts`
**Purpose**: XML sitemap generation for SEO
**Usage**:
- Dynamically generates sitemap for all pages
- Helps search engines index the site
- Configures priority and change frequency

#### `app/favicon.ico`
**Purpose**: Site favicon
**Usage**:
- Browser tab icon
- Displayed in browser bookmarks and tabs

### API Routes (`app/api/`)

#### Authentication APIs (`app/api/auth/`)

##### `app/api/auth/[...nextauth]/route.ts`
**Purpose**: NextAuth.js API route handler
**Usage**:
- Handles all NextAuth.js authentication requests
- Provides session management endpoints
- JWT token generation and validation
- **Endpoints**:
  - `/api/auth/signin` - Sign in
  - `/api/auth/signout` - Sign out
  - `/api/auth/session` - Get session
  - `/api/auth/csrf` - CSRF token

##### `app/api/auth/signup/route.ts`
**Purpose**: User registration API endpoint
**Usage**:
- Creates new user account
- Hashes password with bcrypt
- Generates email verification token
- Sends verification email
- **Request**: POST with user data
- **Response**: Success or error message

##### `app/api/auth/signin/route.ts`
**Purpose**: User sign-in API endpoint
**Usage**:
- Validates user credentials
- Checks email verification status
- Checks user active status
- Returns authentication result
- **Request**: POST with credentials
- **Response**: User data or error

##### `app/api/auth/verify/route.ts`
**Purpose**: Email verification API endpoint
**Usage**:
- Verifies email verification token
- Updates user emailVerified field
- Activates user account
- **Request**: POST with verification token
- **Response**: Verification result

##### `app/api/auth/forgot-password/route.ts`
**Purpose**: Password reset request API endpoint
**Usage**:
- Validates email address
- Generates password reset token
- Sends reset email
- Stores token in database
- **Request**: POST with email
- **Response**: Success message

##### `app/api/auth/reset-password/route.ts`
**Purpose**: Password reset API endpoint
**Usage**:
- Validates reset token
- Verifies token expiration
- Updates user password
- Deletes reset token
- **Request**: POST with token and new password
- **Response**: Success or error

##### `app/api/auth/verify-reset-token/route.ts`
**Purpose**: Validate password reset token API endpoint
**Usage**:
- Checks if reset token is valid
- Verifies token expiration
- Returns validation result
- **Request**: POST with token
- **Response**: Valid or invalid

##### `app/api/auth/change-password/route.ts`
**Purpose**: Change password API endpoint
**Usage**:
- Changes password for authenticated user
- Validates old password
- Updates password hash
- **Request**: POST with old and new password
- **Response**: Success or error

##### `app/api/auth/check-password-requirement/route.ts`
**Purpose**: Check password requirements API endpoint
**Usage**:
- Validates password against requirements
- Checks password strength
- Returns validation result
- **Request**: POST with password
- **Response**: Validation result

##### `app/api/auth/check-user-status/route.ts`
**Purpose**: Check user status API endpoint
**Usage**:
- Checks if user is active
- Verifies email verification status
- Returns user status
- **Request**: GET with user identifier
- **Response**: User status

##### `app/api/auth/validate-session/route.ts`
**Purpose**: Validate session API endpoint
**Usage**:
- Validates current user session
- Checks session expiration
- Returns session data
- **Request**: GET
- **Response**: Session data or error

## File Relationships

### Authentication Flow
1. `app/(auth)/signin/page.tsx` → `app/api/auth/signin/route.ts` → `lib/auth.ts` → `lib/db.ts` → Database
2. `app/(auth)/signup/page.tsx` → `app/api/auth/signup/route.ts` → `lib/email.ts` → Database
3. `middleware.ts` → Checks authentication → Redirects to signin

### Data Management Flow
1. `app/(app)/users/page.tsx` → `components/data-table/data-table.tsx` → `app/api/users/route.ts` → `lib/db.ts` → Database
2. Forms → `components/forms/` → API routes → Validation (`lib/validations/`) → Database

### File Management Flow
1. `app/(app)/files/page.tsx` → `app/api/file-manager/route.ts` → `lib/file-manager.ts` → File system

### Workflow Flow
1. `app/(app)/workflows/transfer-requests/page.tsx` → `app/api/workflows/transfer-requests/route.ts` → `lib/workflows/transfer.ts` → Database

### Dashboard Flow
1. `app/(app)/dashboard/page.tsx` → `components/dashboard/KPITiles.tsx` → `app/api/dashboard/analytics/route.ts` → `lib/dashboard-data.ts` → Database

## Key Patterns

### API Route Pattern
- All API routes follow: `app/api/[resource]/route.ts`
- GET: List/Read operations
- POST: Create operations
- PUT: Update operations
- DELETE: Delete operations

### Component Pattern
- UI components in `components/ui/`
- Feature components in `components/[feature]/`
- Shared components in `components/website-components/`

### Validation Pattern
- Zod schemas in `lib/validations/`
- One schema file per resource
- Used in both client and server

### Database Pattern
- Prisma schema in `prisma/schema.prisma`
- Single Prisma client in `lib/db.ts`
- Migrations in `prisma/migrations/`

---

## Summary

This NextJS Template application follows a well-organized structure:

- **Routes**: Next.js App Router with route groups for auth and app
- **API**: RESTful API routes organized by resource
- **Components**: Reusable UI components using shadcn/ui
- **Database**: Prisma ORM with MySQL
- **Authentication**: NextAuth.js with credentials provider
- **Validation**: Zod schemas for type-safe validation
- **Styling**: TailwindCSS with custom design system
- **Workflows**: State machine-based workflow system
- **File Management**: File upload and management system

Each file has a specific purpose and follows established patterns for maintainability and scalability.
